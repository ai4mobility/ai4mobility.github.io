Cross-attention at the merge: one set of tokens asks, another set answers

In self-attention every word asked every other word in the same sentence. Cross-attention splits those roles: the questions come from one place and the answers come from somewhere else — a different lane, a different sensor, a different moment in time. The model at the centre of this page is small, trained, and runs live in your browser. Drag the vehicles and watch its two questions look at different parts of the same scene.

Same arithmetic as self-attention, different roles

A vehicle on an on-ramp is about to merge into lane 1. Before it moves it needs two answers: who will I be following? and who has to let me in? Everything it needs is in the scene around it: six vehicles and one posted speed limit. The picture below puts the two attention patterns side by side on that scene.

Difference 1
The asker is not in the crowd

Queries come from one source (the merging vehicle's questions); keys and values come from another (the vehicles and the map). In self-attention all three came from the same sentence.

Difference 2
The number of answers is yours to set

You get one output per query. Two questions give two answers whether the scene has three vehicles or thirty. That makes cross-attention the standard way to get a fixed-size answer out of an input whose size varies.

Difference 3
The crowd has no order

Shuffle the vehicles and the answers do not change, because the weighted average does not care what order the list is in. A set of surrounding vehicles has no natural order anyway, so this is exactly the behaviour you want.

The key equation

CrossAttn(Xq, Xkv) = softmax( (XqWQ)(XkvWK)ᵀ / √d ) · (XkvWV) shape: (questions × d)·(d × tokens) → a questions × tokens table, then × (tokens × d) → questions × d
Xqthe askers. Here: the merging vehicle's 2 questions, each a learned vector of d = 16 numbers. Xkvthe answerers. Here: every surrounding vehicle as (distance ahead dx in m, lane, speed in mph), plus one map token carrying the posted speed. WQ, WK, WVlearned projections: what to look for, what each token advertises, what each token hands over if chosen. √dthe temperature, exactly as in self-attention. d = 16 here, so the scores are divided by 4. softmaxturns one row of scores into weights that are positive and sum to 1: the multinomial logit from Module 1, with the tokens as the alternatives.

In words: each question scores every token, the scores become shares that add to one, and the answer is the share-weighted average of what the tokens hand over. Self-attention is the special case Xq = Xkv.

Going deeper (optional): why shuffling the vehicles changes nothing, and what it costs

Reorder the tokens with a permutation matrix P, so Xkv becomes P Xkv. The score table becomes S Pᵀ (its columns are shuffled), the softmax is taken along each row, so the weights are shuffled the same way, A Pᵀ, and the output is A Pᵀ P XkvWV = A XkvWV, because PᵀP = I. The output is invariant to the order of the answerers. Shuffle the questions instead and the answers come back shuffled with them (equivariant). Tab 2 has a button that runs this test on the live model.

Cost: the table has Tq × Tkv entries, against T² for self-attention over the same tokens. When a few queries face a very large input this difference is what makes a model feasible (the Perceiver card in tab 4). Padding is handled with a mask: tokens that are not really there get a score of −∞ before the softmax, which is how one batch can hold scenes with 3 and 8 vehicles.

Source for the equation and the encoder–decoder origin: Vaswani et al. (2017), Attention Is All You Need, §3.2.3. For the permutation argument in general form, see Bishop & Bishop, Deep Learning (2024), ch. 12.

What the model is, exactly

Each token is a vehicle, described by three things: dx, its distance ahead of the merging vehicle (m, negative means behind); its lane (target lane 1 or inner lane 2); and its speed (mph). One extra token describes the map, carrying the posted speed. The two questions are learned vectors, the same idea as the object queries in DETR or the motion queries in MTR (tab 4). Keys come from a small network on each token's features. Values are a plain linear map of the features, so each token's "report" is readable. Parameters in total: .

The scenes are synthetic. Lane 1 and lane 2 each carry a stop-and-go wave, so speed changes along the road and the average speed of a lane is not the speed of the car you will actually follow. The labels come from a written rule: Q1 is the speed of the nearest lane-1 vehicle ahead within 100 m, or the posted speed if there is none. Q2 is the gap to the nearest lane-1 vehicle behind within 100 m, or 100 m ("open") if there is none. The model only ever saw the answers. Nobody told it where to look. The attention patterns above are what it worked out for itself.

Does looking selectively matter? The evaluation

Evaluation close

Baseline
Three of them: the posted speed (or "open") with no model at all; the rule with the lane left out ("nearest vehicle in any lane"); and a network with the same token encoder that gives every token an equal weight (mean-pooling). The last is the fair comparison, because only the weighting differs.
Split, and why it is honest
The test scenes are drawn fresh from the generator and never appear in training. That is honest for one question only: can this mechanism learn a selection rule from answers alone? It says nothing about real ramps. Because the labels come from a rule, the rule itself scores zero error. If you know the rule, write it down. Cross-attention earns its place when the rule is unknown, as it is for real drivers in real merges.

A traveler asks the alternatives: cross-attention with one query is a logit model

Set aside the neural network for a moment. A traveler is choosing how to get from campus to downtown. Their tastes are one vector (how much they dislike time, cost and unreliability). Each alternative is described by a vector of attributes. Put the taste vector in the query slot and the attributes in the key slot, and the dot product q·k is the systematic utility V. The softmax over the alternatives is then the multinomial logit you estimated in your choice-modelling course.

Attribute values are illustrative inputs for a campus-to-downtown trip, chosen to be plausible. They are not survey or agency data. Utility here is V = −μ·(cost + VOT/60 · time + ρ · VOT/60 · buffer), in dollars, where the buffer is the extra minutes you would have to leave early to arrive on time 95% of the time.

What does not carry over

Tastes are computed, not fixed. An estimated MNL has one β per market segment. In a network, q = WQ x, so every traveler, trip purpose or time of day gets its own taste vector from a learned function. That is closer to a mixed logit, with the heterogeneity produced by a function of the context instead of drawn from a distribution.

Attention never chooses. It returns the probability-weighted average of the values, which is an expected outcome. On the merge in tab 2 that is why an ambiguous leader gets you a speed nobody is driving.

IIA comes along too. Press “Add a blue bus”: an identical copy of the express bus takes share from every alternative in proportion, and the two buses together end up with more than one bus had. This is the red-bus/blue-bus problem from Module 1, and plain softmax attention has it for the same reason. In perception it matters directly. A vehicle seen by two overlapping cameras becomes two tokens, so in fusion it gets roughly twice the say. Real systems deduplicate (DETR's set matching, BEVFormer's attention only to the camera views each grid cell actually projects into) instead of assuming the softmax will sort it out.

Where cross-attention lives in transportation systems

For every system you meet, ask the same three questions: who asks, who answers, and how many questions. The last one is the design decision, because it fixes the size of the output no matter how large the input is. Every model detail on these cards was read from the original paper.

How big is the table? A cost check for your own design

Entries per head per layer. The METR-LA window (207 detectors × 12 five-minute steps = 2,484 tokens) is the one from the Transformer as an architecture companion. With self-attention it needs 6,170,256 entries. The DETR preset assumes a 1280 × 720 camera frame: DETR’s backbone reduces each side by a factor of 32, which leaves 23 × 40 = 920 feature tokens.

Where it breaks, measured on the merge model

Every row below was measured on the same trained model you dragged around in tab 2. Each failure is a property of the mechanism, not of this toy, and each one has a standard fix in the published systems.

1 · The weights must sum to one

Fix used in practice: give the model somewhere to put "nothing". DETR has a "no object" class for unused slots, and language transformers park weight on separator tokens (the [SEP] sink you saw in the self-attention companion).

2 · Between two lanes, it averages

Try it: tab 2 → “Cut-in in progress”, then drag the blue-outlined vehicle up and down.

3 · More vehicles than it ever saw

4 · Queries do not talk to each other

Inside one cross-attention layer each row is computed on its own. Question 1 has no idea what question 2 found. Here that is harmless, because one looks ahead and the other behind. In detection it is not: two of DETR's 100 slots can lock onto the same car. DETR therefore alternates cross-attention with self-attention among the queries and trains with a one-to-one matching loss, so duplicate answers are penalised.

5 · Attention is not an explanation

The weights here happen to be readable because the task is a clean selection. The cross-attention sanity-check lab (in development) shows a camera-to-CAN model whose head-averaged map looks diffuse while one head routes almost perfectly. There, ablation and counterfactuals were the evidence, not the picture.

Fit card: cross-attention

Idea in one sentence
A fixed set of questions takes a learned, content-dependent weighted average over a different set of tokens, so each question gets its own summary of the other source.
Why it works (the logic)
Scores are dot products between what the question looks for and what each token advertises. The softmax turns them into shares (an MNL over tokens), and the answer is the share-weighted report. Relevance is computed from the content, so the token that matters can change with every scene.
Fits these tasks
Fusing two sources (camera ↔ radar/CAN, image ↔ text, agent ↔ map); a fixed-size output from a variable-size input (BEV grid, N object slots, future horizons); compressing a huge input (a few latents over a whole detector network). Leverage labels: extraction · prediction · classification.
Needs this data
Paired examples of both sources, time-synchronised and in a shared coordinate frame, with labels only for the final answer. Thousands of scenes for a toy like this one; millions of frames for BEV perception (nuScenes, Waymo Open). Mostly held by OEMs, AV developers and the public datasets.
Breaks when
Nothing relevant is present and no token means “nothing here”; the relevant token is ambiguous (it averages); duplicated tokens (IIA); sources are not calibrated or synchronised (a 100 ms camera–radar offset at 30 m/s is 3 m); scenes far larger or stranger than training; attention maps are read as explanations.
Keep the classical method when
The selection rule is known and stable (lead-vehicle selection in ACC, gap acceptance for a merge assist): write the rule down, and it scores zero error at no training cost. Keep Kalman or track-level fusion when the sensors are few, well calibrated and need certifiable behaviour.
