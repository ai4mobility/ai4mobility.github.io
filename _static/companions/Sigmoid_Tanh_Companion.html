Sigmoid, Tanh & Softmax — the squashing functions you already use

You have fitted these before. Every binary logit mode-choice model you have ever estimated is a sigmoid; every multinomial logit route-choice model is a softmax. This companion starts from that, generalizes to signal-control policies, then follows the same curves into the two facts that shaped the entire history of deep learning: saturation and the vanishing gradient. Everything runs locally in your browser — nothing to install, no data leaves the page.

The binary logit model is a neuron

Start with something familiar. A traveler chooses between transit and car. Random utility theory gives each alternative a systematic utility, and the probability of choosing transit is the binary logit formula. Write it out, cancel the common term, and a sigmoid falls out — the same function, with the same shape, that sits inside every neural network.

binary logit P(transit) = eμVt / (eμVt + eμVc) = 1 / (1 + e−μ(Vt−Vc)) = σ(μ·ΔV) a neuron a = σ(z), z = w·x + b where σ(z) = 1 / (1 + e−z)

Same equation. The scale parameter μ is the weight; the alternative-specific constant is the bias; the attribute difference is the input. What changes in a neural network is not the function — it is that w and b are learned by gradient descent instead of estimated by maximum likelihood, and that thousands of these units get stacked.

Push μ toward 3: the curve stiffens into a step — travelers become deterministic, choosing the better alternative almost every time. Pull μ toward 0: the curve flattens to a coin flip regardless of utility. In neural-network language, the weight controls how sharply the unit commits. The bias slides the whole curve left or right, setting where the threshold sits — exactly what an alternative-specific constant does.
Read the pre-activation z as a log-odds score: z = ln(P / (1−P)). A neuron does not output a probability internally — it outputs evidence on a log-odds scale, and the sigmoid is the dictionary that converts evidence into probability. Every logit coefficient you have ever interpreted is a weight in this sense.

Why a squashing function at all?

Because without one, depth buys you nothing. Stack two linear layers and you get W₂(W₁x) = (W₂W₁)x — still a single linear model, no matter how many layers you add. The nonlinearity between layers is what makes a deep network more expressive than a regression. Sigmoid was the first popular choice for two reasons that mattered in 1986: it is smooth (so it is differentiable everywhere, which backpropagation needs), and it is bounded (so a unit cannot blow up).

Keep this test in your pocket for the rest of the course: if you remove every nonlinearity from an architecture and it still does the job, you did not need the network. A linear model that you can interpret and defend to a review panel is almost always the better answer.

Sigmoid vs. tanh: the same curve, recentered

Tanh is not a different idea. It is a sigmoid stretched to twice the slope and shifted down so it straddles zero. The algebra is exact, and you can check it below by overlaying the two. What differs is the range, and range is what decides which one belongs in which slot of a mobility model.

tanh(z) = (ez − e−z) / (ez + e−z) = 2σ(2z) − 1 range σ: (0, 1) — one-sided, never negative | tanh: (−1, 1) — signed, zero-centred
σ(z) tanh(z) 2σ(2z) − 1
Why zero-centring matters. Sigmoid outputs are always positive, so every input a downstream unit receives has the same sign. The gradients for all of that unit's weights then share a sign too, and the update can only move diagonally — all up or all down — forcing a zig-zag path to the optimum. Tanh's outputs average near zero, which removes that bias. This is the practical reason tanh replaced sigmoid in hidden layers through the 1990s and 2000s.

Which one for which mobility quantity?

UseFunctionWhy
Probability of congestion, crash, lane changesigmoid The quantity is bounded in [0,1] and one-sided. This is the output layer of a binary classifier.

Deviation from a desired speed or headwaytanh The natural zero is "on target", and errors go both ways.

Tanh is already in your car-following models

A driver closing on a slower leader decelerates; a driver falling behind a faster leader accelerates; and in both directions the response flattens out at the limit of what tyres and engine can deliver. That is an odd-symmetric saturating function of the speed difference — which is to say, a scaled tanh. Vary the sensitivity below and watch the two regimes: near Δv = 0 the response is essentially linear (this is the classical linear car-following model), and far from zero it saturates.

Drop k to 1: the driver is hair-trigger, slamming to full braking for a 2 m/s difference. Raise k to 14: sluggish, barely responding until the gap is closing fast. Same parameter, same meaning as the weight w on page 1 — it is the slope through the origin, and it decides how much of the curve you actually operate on.

Softmax: the same logit, with more than two alternatives

A sigmoid answers "transit or car?" — one probability, two alternatives. Real mobility decisions rarely stop at two. Which of five routes? Which of four signal phases? Which of eight vehicle classes is this blob in the camera frame? The generalization is softmax, and once again you already know it: softmax is the multinomial logit model.

softmax softmax(z)i = ezi / Σj ezj multinomial logit P(i) = eμVi / Σj eμVj ← identical, with zi = μVi two alternatives softmax([z₁, z₂])₁ = σ(z₁ − z₂) ← sigmoid is the N = 2 case

Three properties earn their keep, and all three have a discrete-choice reading you already own:

PropertyWhat it meansThe discrete-choice reading
Outputs sum to 1The result is a probability distribution over the alternatives, not N independent scores. Choice shares across a full choice set must add to one.
Shift-invariantsoftmax(z + c) = softmax(z). Adding the same constant to every score changes nothing. Only utility differences are identified. You cannot estimate a level of utility, only who beats whom.
Temperature τsoftmax(z/τ). Small τ → near argmax; large τ → near uniform. τ = 1/μ. It is the logit scale parameter, inverted — the same decisiveness knob from page 1.
Shift-invariance is not a curiosity — it is what makes softmax computable. Since subtracting a constant changes nothing, every real implementation subtracts max(z) before exponentiating, so the largest exponent is e⁰ = 1 and nothing overflows. If you ever write softmax by hand and skip that step, a score of 800 gives you Inf/Inf = NaN. That is the same feature-scaling failure from page 4, in a different costume.

Independence of Irrelevant Alternatives. Watch the A : C odds ratio while you tick the clone on and off — it does not move. Softmax splits B's share between B and B′ and leaves every other ratio untouched. For genuinely distinct alternatives that is the right behaviour. For a duplicate it is nonsense: two names for one road should not take a bigger combined share than one name for it. This is the red-bus / blue-bus problem, and it is the reason nested and mixed logit exist. The identical flaw rides into deep learning the moment you softmax over classes that overlap — "sedan" and "car", "bus" and "transit vehicle" — and it shows up as a confidently split, wrongly calibrated prediction.

Signal control: turning scores into a phase decision

A reinforcement-learning signal controller reads the state of the intersection and produces one score per phase. Those scores are not probabilities and they are not comparable across intersections — they are just numbers. Softmax converts them into an actual policy: a distribution over which phase to serve next. Here the score is simply the queue on that phase's approaches, and τ is the controller's decisiveness.

Why softmax and not just argmax?

"Serve the phase with the highest score" is argmax, and argmax has two fatal properties for learning: its derivative is zero everywhere it is defined, so no gradient can flow back into the scores; and it never tries anything it does not already believe in, so it cannot discover that a belief is wrong. Softmax is the smooth, differentiable relaxation of argmax — exactly as sigmoid is the smooth relaxation of a step function. That is the same trade, made twice.

The engineering reading. Temperature is not a hyperparameter you tune once and forget — it is the explicit dial between "act on what I have learned" and "check whether I am wrong". Deployed RL signal controllers anneal it: high early in training, near zero at deployment. Anneal too fast and you get the red curve, which is worse than exploring at random. Two things follow. First, when a paper claims an RL controller beats actuated control, the exploration schedule belongs on your list of questions, next to the baseline and the test corridor. Second, an RL controller that has never served a phase cannot have learned anything about it — so ask what the policy does at 3 a.m., during an incident, or on a movement that is rare in the training data. Those are exactly the states where the stale estimate lives.

The gradient, and where softmax shows up

softmax + cross-entropy ∂L/∂zi = pi − yi ← the Jacobian cancels, exactly as on page 6 softmax Jacobian ∂pi/∂zj = pi(δij − pj) ← → 0 as any pi → 1: softmax saturates too

The first line is the multi-class version of the cancellation you will meet on page 6, and it is why "softmax + cross-entropy" is written as one layer in every framework. The second line is the warning: a softmax that has already committed to one alternative has a vanishing Jacobian, so a confidently wrong classifier is as hard to correct as a saturated sigmoid.

The deployment trap worth remembering. Softmax always returns a distribution that sums to 1 — it has no way to say "none of these". A vehicle classifier trained on car / truck / bus / motorcycle will assign a confident label to a shopping cart, a shadow, or a deer, because the only outputs it owns are those four. If you are evaluating an AI traffic-monitoring product, ask what happens on out-of-distribution objects, and treat a high softmax probability as a ranking, not as a calibrated confidence, unless the vendor can show you a reliability diagram.

Saturation: a neuron that has pegged its detector

Here is the flaw that these two functions carry by construction. Both are flat in the tails. Flat means the derivative is near zero, and the derivative is the only channel through which learning happens. A unit driven far from zero stops responding to change — and stops learning.

The transportation version of this failure

You have seen saturation destroy information before. A loop detector reporting occupancy pegs near 100% once the link jams. From that moment the reading cannot distinguish a ten-vehicle queue from a two-hundred-vehicle queue — the derivative of the reading with respect to the true state has gone to zero. The detector is still reporting, confidently, and it is telling you nothing you can act on.

A saturated neuron is a pegged detector. Its output is a confident 1 (or 0). Nudge its weights and the output barely moves, so the loss barely moves, so the gradient is essentially zero, so the optimizer has no signal about which direction to go. The unit is frozen.

The worst case is saturated and wrong. A unit that is confidently predicting "free flow" on a jammed link has both a large error and no gradient to fix it. This is not a hypothetical — on page 5 you will cause it on purpose, and watch a model with two parameters need 400× more iterations to dig itself out.
Softmax saturates in exactly the same way. Its Jacobian is ∂pi/∂zj = pi(δij − pj), which goes to zero as any pi → 1. A classifier that is already certain, and a softmax policy at low temperature, are both pegged detectors — same disease, one dimension higher. This is why attention scores are divided by √d before the softmax: with d = 64, raw dot products run in the tens, the softmax pegs to one-hot, and no gradient flows. The scaling is a temperature, and its job is to keep the softmax off its tails. Module 4 returns to this.
A number worth carrying: at |z| = 6, σ′ ≈ 0.0025 — one hundredth of its best value. And feature scale is what puts you there. If you feed raw density (say 80 veh/mi/ln) into a unit with weight 1, then z = 80 and σ′(80) ≈ 10−35. The unit is dead before the first gradient step. This is the whole reason inputs get standardized, and it is the most common cause of a network that "won't train" in a student project.

Depth: where saturation becomes the vanishing gradient

Backpropagation assigns blame. To tell layer 1 how it contributed to the error at the output, the chain rule multiplies one derivative per layer along the way. Multiply enough numbers smaller than one and the blame arriving at the early layers rounds to nothing — they never learn. This single fact is why neural networks were stuck at two or three layers until roughly 2011.

Leave |z| = 0 — the most generous case, every unit sitting at its steepest point — and slide L out to 14. Sigmoid delivers about 10−9 of the gradient to the first layer. Those weights are frozen at their random initial values; the network is deep on paper and shallow in practice.
Now slide |z| up, and watch tanh lose. At |z| = 3, σ′ ≈ 0.045 but tanh′ ≈ 0.0099 — tanh has fallen below sigmoid. Tanh's advantage is real only near the origin, where its slope is 1 against sigmoid's 0.25. Once units drift into their tails, tanh saturates harder, because it compresses the same output range across a steeper curve. ReLU holds a derivative of exactly 1 for any active unit, at any magnitude — which is the whole reason it took over around 2011 and why it is the default you will meet in every architecture later in this course.

So are sigmoid and tanh obsolete?

No — they were displaced from hidden layers, not from the field. They remain the right tool wherever you need a bounded output rather than an unbounded feature:

WhereWhichWhy it survives there
Output layer, binary classificationsigmoid You need a probability. Paired with cross-entropy loss, the saturation problem cancels out — page 5 shows this.
Output layer, multi-classsoftmax Softmax is the multi-alternative sibling of sigmoid — the multinomial logit, which you already know.
LSTM and GRU gatessigmoid A gate must mean "fraction admitted", which is bounded in [0,1] by definition.
Bounded control heads (steering, throttle)tanh The action is physically bounded and signed; the network should not be able to command 40 m/s².
Attention weightssoftmax Same logit machinery, applied to "which input do I read from" — Module 4 builds this.

The experiment worth running

Set Initialization → confidently wrong, then run each loss in turn and compare. The two runs differ by one term in the gradient:

squared error ∂L/∂z = (a − y) · σ′(z) ← saturated unit ⇒ σ′ ≈ 0 ⇒ no gradient cross-entropy ∂L/∂z = (a − y) ← the σ′ term cancels; gradient stays ≈ ±1
Cross-entropy was designed to cancel exactly this term. That is not a convenience — it is why a sigmoid output layer is still perfectly usable in 2026 while sigmoid hidden layers are not. There is no matching cancellation in the middle of a network, so nothing rescues a saturated hidden unit. If you take one practical rule from this page: never pair a sigmoid output with squared-error loss. It is a quiet, common bug, and it looks exactly like "my model won't learn."
A second thing to try. Reset, then push the learning rate to 2.0 with the confidently-wrong start and cross-entropy. Watch the fitted curve overshoot past the data before settling. Saturation and step size interact: too large a step throws units into the tails, where they can no longer generate the gradient needed to come back.
