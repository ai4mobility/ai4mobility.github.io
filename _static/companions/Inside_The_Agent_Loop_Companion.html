Inside the agent loop

An agent repeats one step: read the whole conversation, write a tool call or an answer, then read the result. Here an open-weights model, Qwen3, runs that loop with the same tools and the same questions as the Claude page. Because its weights are open, you can read every word it reads and the probability behind every choice it makes: whether to call a tool, which tool, and which answer it believes.

One step, and what the probes read

How the model chooses: a logit model you already know

At each token, the model gives every possible next token a score and turns the scores into probabilities. That is the multinomial logit you use for mode or route choice, with about 150,000 alternatives instead of a handful.

P(k) = eVk / Σj eVj
kone alternative: a next token, or one tool on the menu
Vkthe model's score (utility) for it, computed from everything in the prompt
P(k)the probability the model gives it

In words: the model picks the alternative with the highest utility, softly, exactly like an MNL. Changing the prompt (a better tool description, a new result) changes the utilities, and so the choice.

Going deeper (optional): how a tool's probability is read off the model

A tool call is written as text: <tool_call> {"name": "work_zones_on_street", ...}. Two choices hide in it. First, the token <tool_call> versus any other first token: that is call or answer. Second, the tool's name, which may be several tokens (work, _z, ones…). The name's probability is the product of its tokens' probabilities (the chain rule), so its utility is the sum of their log-probabilities. Normalising over the names on the menu gives the probability of each tool, given a call. This is the same as computing the choice probability of a nested logit's lower nest.

Probabilities here are at temperature 1; the run itself samples at temperature 0.7, which makes a likely choice more likely still.

Belief: which answer does the model hold right now?

To watch an answer form, each step also asks a copy of the conversation one extra question: "which of these four answers is best?" One is right; three are the traps from the closed-model page (for example "lane 4 of 5 is closed"). The probability of each letter is the model's belief. Each answer is shown at A, B, C and D in turn, and the four readings are averaged, so a model's habit of preferring one letter cannot decide. When the four readings disagree, the belief is unstable, and the page says so.

What it shows, and what it does not

How far to trust these readings, when this way of looking inside an agent is worth it, and how to run it on your own tools.

Fit card — Reading an open model's probabilities to understand an agent

Idea in one sentence
Run the agent on an open model and, at each step, read the probabilities behind its choices (call or answer, which tool, which answer) on a copy of the conversation.
Why it works (the logic)
The model's choice is a logit over alternatives. Its utilities are visible when the weights are open, so you can see a wrong choice coming, and see which words in a description or result move it.
Fits these tasks
Debugging tool descriptions and results; teaching how agents work; checking whether a model's answer is stable before you trust it. judgment classification
Needs this data
An open-weights model you can run (a laptop is enough for a small one) · your tools behind MCP · questions with checked answers and the traps you expect.
Breaks when
The small model you can open behaves differently from the large one you deploy; the probe question itself nudges the model; one seed and a few questions make a story, not a statistic.
Keep the classical method when
You only need to know whether the final answers are right: grading answers against checked answers (the closed-model page) is simpler and works with any model.

Check yourself

1. In tab 4, compare the new tool's probability at the first step in B and in C for busch_lanes. Which sentence of C's description would you test first, and how would you show it is that sentence?

Notes

In C the engineer's description takes almost all of the probability; in B the plain one gets about a third of it. Start with the sentence that matches the words of the question (a street, near a point, which lanes). To show it is that sentence, remove or reword only that sentence, rebuild the prompt, and read the probability at step 1 again; then do the same for each other sentence. The sentence whose removal drops the probability most is doing the work. It is the same ablation you ran in A5.1, one sentence at a time.

2. In tab 3, look at mckinley_warmup in setups A and C. Both answers are graded partly, yet after the first tool result the model's belief in the right answer falls close to zero. What does that tell you about the answer a model writes and the answer it would pick from a list? Where would you put a check: in the tool, in the harness, or with a person?

Notes

The two can disagree. The probe asks a different question (pick one of four full answers), so it shows what the model leans toward, not what it will write; here the model wrote part of the right answer while preferring a trap from the list. Neither is a guarantee. Put the check where the fact is made: the tool result should state the fact in the words the answer needs (the lane order from the median), and the harness or a person should compare the answer with the tool result before anyone acts on it.

3. The prompt grows by every result (tab 3, bottom). For a SUMO study with 30 tool calls, what would you change in the tools' results so that the model still reads the instructions at the top?

Notes

Make each result short and already read: the answer first (the lane, the count, the status), a summary instead of every record, and a line saying what was left out and how to ask for it. The harness can also replace old results with short summaries. Then measure it: prompt tokens per step, and whether the answers stay right as the calls pile up.

Run it yourself

In the class folder, M5-8_AI_Agents_and_RL/agent_tools_demo/. It needs Python with torch, transformers and mcp; the first run downloads the model (about 4 GB). A laptop CPU is enough.

python inside_loop.py busch_lanes C          # one run with the probes (about 1 to 3 minutes)
python inside_loop.py --all                  # the nine runs on this page
python inside_loop.py busch_lanes C --think  # the reasoning run (tab 5)
python inside_loop.py busch_lanes C --model Qwen/Qwen3-4B   # a larger model, if you have the memory
python build_inside_companion.py             # rebuild this page
