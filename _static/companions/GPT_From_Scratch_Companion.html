A GPT You Can Read

Every step of a decoder-only transformer, running on a real model we trained here on — vehicle-owner complaint narratives filed with NHTSA. Nothing on this page is illustrative: the matrices you click through are the trained weights of —-parameter model in gpt_from_scratch.py, and each one was re-derived a second time in plain NumPy to make sure the arithmetic is what it claims to be.

A transformer has exactly one job

Given the words so far, put a probability on every word that could come next. That is the whole training objective — there is no second one. Everything a language model later does for you (classify a complaint by component, pull the failure mode out of a crash narrative, draft a work-zone memo) is this objective, plus a small head bolted on afterwards.

The mobility task this model is trained on

Owners file complaints with NHTSA in free text. An agency analyst reads them and assigns a component code. The corpus below is — of those narratives (— word tokens), and the model's only task is next-word prediction on them. To do it at all well, it has to notice that disengaged follows adaptive cruise control more often than it follows windshield — which is to say it has to learn something about the failure modes in the corpus. That byproduct is what you later fine-tune.

Where the parameters are

Two thirds of this model is the word table; in GPT-3 the proportion is the other way round. Note the output head costs nothing: it is the same matrix as the token embedding, reused — a table that reads words in can score words on the way out.

Why position has to be added at all

Attention is a weighted average, and an average does not care what order its terms came in. Shuffle the tokens of a sentence and, with the position table switched off, every output vector comes back identical, just shuffled the same way. We measured it on this model:

—
max abs difference, position OFF
—
max abs difference, position ON

Left: numerically zero — the model literally cannot tell the truck hit the car from the car hit the truck. Right: large, because the position rows no longer line up. A CNN gets ordering for free from the shape of its kernel; a transformer has to be told, and the telling is one addition.

Measured with the causal mask switched off, because the triangle carries order information of its own: it tells every token which others came before it. That is why a decoder with no position table still half works, and an encoder with none does not.

This is the hook for your own data. Nothing says the position table has to encode word index. For a detector sequence it can encode the time of day; for a corridor it can encode free-flow travel time from the upstream station. Whatever you put in this one table is the only notion of “where” the model has.

An honest cost of the word-level tokenizer

This model's vocabulary is whole words, so every attention row on this page is readable. The price: any word outside the top — becomes <unk>, which happens to — of validation tokens — model numbers, trim levels, misspellings. Real GPTs use byte-pair encoding for exactly this reason, and can spell a word they have never seen.

Q, K, V — three matrices, one input

The single most common confusion about attention is that Q, K and V are three different inputs. They are not. They are three different linear views of the same vector, produced by three different weight matrices that the model learns. In self-attention the same token supplies all three.

How they are defined

# three separate matrices, D x D each self.W_q = nn.Linear(D, D, bias=False) self.W_k = nn.Linear(D, D, bias=False) self.W_v = nn.Linear(D, D, bias=False) # one input x: (B, T, D) q = self.W_q(x) # (B, T, D) k = self.W_k(x) # (B, T, D) v = self.W_v(x) # (B, T, D)

Production code usually fuses these into one (D, 3D) matrix for speed and then slices. That is the same arithmetic; keeping them apart costs nothing and makes the picture literal.

Read the shapes, not the names. Each of q, k and v is the same size as x. Nothing has been compressed yet; the vector has just been rotated three ways.

What each view is for

viewthe role it plays
q — querythe question this token is asking. For disengaged: “which system was it that disengaged?”
k — keythe advertisement this token posts. For control: “I am the end of a named vehicle system.”
v — valuethe cargo it hands over if it is attended to. What actually gets averaged — and it is not the same vector as the key.

Query and key are compared; only the value is moved. Separating "what makes me relevant" from "what I contribute" is why one head can route by grammar while the information it moves is about meaning.

A familiar shape. A gravity model also scores every origin–destination pair and normalises the row — but its score is a fixed function of distance. Here the score is a learned function of what is in the two tokens, and it changes sentence by sentence.

Going deeper — why a dot product is a reasonable way to ask “is this relevant?”

q·k = ‖q‖ ‖k‖ cosθ. The cosine is the part that carries meaning: it is large when the two vectors point the same way in the head's dh-dimensional space, and the model is free to learn which directions of that space matter by choosing W_q and W_k. The magnitudes act as a learned confidence: a token can make itself loud (large ‖k‖) or a query can be insistent (large ‖q‖). Because W_q and W_k are separate, the score is not symmetric — token i can attend hard to token j while j ignores i, which a correlation matrix or a symmetric adjacency matrix cannot express. Vaswani et al., Attention Is All You Need, NeurIPS 2017, §3.2.1; Bishop & Bishop, Deep Learning, §12.1.

The dot product — every token against every token

One matrix multiply computes all T×T comparisons at once. That single line is what makes a transformer fast on a GPU, and it is also the line that makes it quadratic in sequence length.

# q, k: (B, H, T, dh) scores = q @ k.transpose(-2, -1) # (B,H,T,dh) @ (B,H,dh,T) -> (B,H,T,T) # scores[i, j] = q_i . k_j = sum over the dh dimensions of this head

The transportation reading

A T×T matrix whose rows sum to one, applied to a stack of per-location vectors, is something you have built before: an adjacency or weight matrix in a spatial model, a transition matrix in a Markov route model, the influence matrix in a cell-transmission scheme. The difference is not the shape.

Yours is declared and fixed. This one is computed from the content, and it is different for every input. That is the entire argument for attention over a fixed graph — and also the reason it needs far more data than your declared matrix did.

Why divide by √dhead

scores = scores / math.sqrt(d_head) # d_head = —, √ = —

A dot product of two dh-dimensional vectors is a sum of dh terms, so its spread grows like √dhead. Feed scores that large into softmax and one weight goes to nearly 1 and the rest to nearly 0: the row stops being an average and becomes a hard pick, and the gradient through softmax goes flat — the same saturation you already know from a logit model with a scale parameter set far too high. Measured on this sentence:

The scale is the difference between a weighted average and a lookup. On a bigger model with a bigger dhead the gap is far larger than this.

Going deeper — where the √d comes from

Take q and k with independent entries of mean 0 and variance 1. Their dot product is a sum of dhead independent products, so it has mean 0 and variance dhead — standard deviation √dhead. Softmax cares about score differences, so a spread that grows with dhead would make the same architecture behave differently at every width. Dividing by √dhead returns the spread to order 1 and makes the layer width-independent, which is the real reason it is there: not to fix a number, but to stop the number from depending on a design choice. Vaswani et al., Attention Is All You Need, NeurIPS 2017, footnote 4.

Check it yourself: the entries here are not unit-variance (they are what training produced), which is why the measured spread is — rather than —. The argument fixes the scaling with width, not the absolute value.

Why the mask, and why −∞

scores = scores.masked_fill(~mask, float("-inf")) # mask = torch.tril(ones(T, T)) -> True on and below the diagonal

A GPT is trained to predict token i+1 from tokens 0..i. All T predictions are made in one pass, so the only thing stopping token i from simply reading its own answer is this triangle. −∞, not a large negative number: softmax sends exp(−∞) to exactly 0, so a forbidden token gets exactly no weight and no gradient.

Ask it to generate, though, where there is no future to read, and the illusion ends. Same prompt, both models:

mask off —

A loss that drops too fast is a leak, not a breakthrough. Perplexity near 1 on a language task is not a result; it is a bug report.

Encoders do not do this. BERT, and the encoders in the traffic transformers you read, use the full square: every token sees every token, because they are not predicting the next one. The mask is what makes this model generative and left-to-right. If your own task is “label this whole sequence”, you probably want the square.

Softmax, implemented rather than imported

Softmax appears twice in this model: once per attention row, turning scores into weights, and once at the very end, turning D-dimensional output into a probability over all V words. It is four lines, and one of them is there only to stop the other three from producing nan.

The implementation

def softmax(scores, dim=-1): m = scores.max(dim=dim, keepdim=True).values z = scores - m # every entry now <= 0 e = torch.exp(z) return e / e.sum(dim=dim, keepdim=True)

Subtracting the row maximum is exact, not an approximation: multiplying numerator and denominator by the same e−m leaves every probability unchanged. After it, the largest exponent is e0 = 1 and nothing can overflow.

One nan in one row poisons every weight in the model at the next backward pass, and the loss prints as nan forever after with no clue where it started. This is the most common way a hand-written transformer dies.

You already estimate this model

softmax(s)_j = exp(s_j) / Σ_k exp(s_k) P(j) = exp(V_j) / Σ_k exp(V_k) # multinomial logit

Same formula. The attention score q_i·k_j plays the part of the utility of alternative j, the √dhead division is a scale parameter, and the row of weights is a choice probability over “which earlier token do I read from”. At the output layer the alternatives are the V words, and training by cross-entropy is maximum likelihood on exactly that logit model.

What transfers from your MNL intuition: shifting every utility by a constant changes nothing (that is why the max subtraction is safe); the IIA-style “probability mass has to come from somewhere” trade-off is why attention to one token necessarily takes weight from another.

Many heads, and what surrounds them

One attention row is one opinion about what matters. A block runs H of them in parallel on disjoint slices of the vector, then glues the results back together. Around that sits the part that does the actual thinking about each token on its own.

Do not over-read these pictures. A strong weight is not proof that a token “mattered”: what is moved is the value vector, so a heavily-weighted token with a small value contributes little. Attention maps are a hypothesis-generator, not an explanation (Jain & Wallace, NAACL 2019). If a head's map is the evidence in your paper, ablate the head and show the metric moves.

The other half of the block

x = x + attn(ln1(x)) # tokens talk to each other x = x + mlp(ln2(x)) # each token, alone, non-linearly

Attention is a weighted average, and a weighted average of vectors is still a linear map — stack a hundred of them and you still have a linear model. The MLP is where the non-linearity lives and where most of the parameters outside the word table sit (— of this model). It widens each token to —, applies GELU, and narrows it back.

The two lines that make depth trainable

The residual x + gives the gradient a path back to the input that passes through no weight matrix at all. Without it, the vanishing-gradient problem you met in the backprop notes returns at about six layers.

LayerNorm before each sublayer (not after, as in the 2017 paper) re-centres and re-scales each token's vector so the next matrix always sees inputs of a predictable size. Moving it before is what removed the learning-rate warmup that early transformers needed to train at all.

Read a block as one sentence: copy the token forward unchanged, and add to it (a) what it learned by looking at other tokens, and (b) what it worked out on its own. That is the whole architecture, repeated — times.

Does it beat the baseline?

A perplexity on its own means nothing. Perplexity is “how many equally likely words is the model effectively choosing between at each position”, so a uniform guesser scores the vocabulary size. Two counting baselines — neither of which has a single learned parameter — are what the transformer has to beat before any of its machinery has earned its place.

Reading the number

A perplexity of — means that at each position the model is effectively choosing between about that many words — out of a vocabulary of —. Counting the previous word alone already narrows the field to about —; the transformer's contribution is the step from there, bought with 1.5 million parameters and half an hour.

Report the ratio, not the loss. A cross-entropy of 3.74 sounds like nothing; “still choosing between forty words” is a sentence an agency reviewer can argue with, which is the point of putting a baseline next to it at all.

Ask the same question of your own model. Persistence and a historical average are the two baselines for traffic prediction that play the roles the unigram and the bigram play here — free, parameterless, and surprisingly hard to beat at short horizons.

The split, and why it is honest

  • Split by whole complaint, never mid-narrative — no sentence is half in each side.
  • — verbatim duplicate narratives removed before splitting. Re-filings and dealer form letters repeat; leave them in and validation measures memorisation.
  • The vocabulary is built on the training half only, so test words the model never saw are honestly <unk> (— of validation tokens).

Where this model breaks

  • It has read one inbox. Complaint English only. Point it at an FDOT maintenance log and perplexity collapses — the domain shift you already expect when a model calibrated in Tampa is moved to Orlando.
  • It is — parameters. GPT-3 is 175 billion, about — times larger, on a corpus roughly a million times bigger. Fluency at this scale is local: a clause is plausible, a paragraph is not.
  • Fluent is not true. Nothing in the objective rewards a correct claim, only a likely word. A generated narrative that reads like a real complaint is still fiction, and this is exactly the failure mode you must design around before any LLM output reaches an agency document.
  • Context is — tokens. Anything earlier is gone. A long crash narrative does not fit, and the model cannot refer back to its start.

When to reach for this — and when not to

Fit card — decoder-only transformer (GPT-style)
Idea in one sentence
Predict the next token from the tokens before it, using attention weights computed from the content of the sequence itself rather than declared in advance.
Why it works (the logic)
Every position can pull information from any earlier position in one step, and how much it pulls is learned and input-dependent — so a single model can route differently for different inputs instead of applying one fixed filter.
Fits these tasks
Free-text complaint and crash narratives, log and report drafting, sequence continuation and simulation of trajectories or phase sequences, and any pretraining you intend to fine-tune later. Leverage: generation · extraction · prediction.
Needs this data
Long sequences, in volume, with no labels — the supervision is the shift by one. Millions of tokens for a toy like this; billions for anything general. Agencies hold plenty: 311 text, crash narratives, maintenance logs, detector archives.
Breaks when
Sequences are short or few; the quantity is continuous and smooth (a well-posed regression beats it); the domain shifts away from the training corpus; you need a calibrated probability rather than a plausible continuation; or T grows — cost is quadratic in sequence length.
Keep the classical method when
A count-based or Markov model already gets you there (the bigram on tab 8 is free and within a factor of — of this model); the relationships really are fixed and known, in which case your declared adjacency matrix is a strong prior the transformer must learn from scratch; or you need to defend every coefficient in a public document.
